# dsh-ofttold-memory · 常被提起的记忆

[English](README.md) · **中文**

把你的记忆放进**每一个**会话。

它不是存储工具。一条笔记躺在硬盘上，只有在被需要的那一刻摆到模型面前才有用。而「记得每个会话开头去读索引」本身是个要求——要求模型在注意力最满的时候还稳定地做某件事，那正是这类要求最容易失效的条件。这个插件把那个要求删掉了：它从你已经在维护的 markdown 里取出几节，作为常驻上下文注入一次。

注入之后那条消息就留在历史里，后面每一轮都看得见。这就是全部把戏。

名字来自机制本身：**oft-told**，反复被讲过的那些事。

---

## 开箱即用

```sh
dsh plugin --profile web add /absolute/path/to/dsh-ofttold-memory
```

**装完就完了。** 第一次运行会自动在 `~/.dsh/ofttold-memory/` 建好文件夹和一份起始文件 `MEMORY.md`，结构已经填好，你只要把内容换成自己的。

**它不会往你已有的笔记文件夹里塞东西。** 把 `memoryDir` 指向一个已经有 markdown 的文件夹（日记、索引、规矩文件都算），插件只读取、不添加——起始模板只在文件夹不存在或空着的时候才建。

之后每个会话开头，`MEMORY.md` 里「常被提起」那一节会自动出现在上下文里。想改就改那个文件，**不用碰任何配置**。

---

## 为什么是「一个文件夹 + 几节」

大多数记忆方案都在回答「怎么存」。这个插件只回答「怎么让它在眼前」。所以它不做检索、不做嵌入、不做数据库——**只做一次注入**。

代价是一节几百 token，每个会话一次。收益是模型不用再问「项目在哪」「哪些东西不能动」。

**判断标准只有一条：不在眼前就会做错事。** 不是「重要」，不是「常提到」，是「这次没看到就会出错」。按这条标准写，八条就够；按「重要」写，永远装不下。

## 三个旋钮，没别的

| 配置项 | 默认 | 干什么的 |
| --- | --- | --- |
| `memoryDir` | `~/.dsh/ofttold-memory` | 记忆文件夹。第一次运行自动创建，可以不管。 |
| `sections` | `["Oft-told", "常被提起"]` | 要常驻哪几节。直接写小节名。 |
| `maxChars` | `600` | 每节字符上限。600 字符约 400 token，每个会话一次。 |

其余几项（`header`、`refreshIntervalMs`、`refreshAfterMessages`、`workspaceRelative`）都有能用的默认值，正常人不用改。

### 在设置页里改

装好之后，「设置 → 插件 → 常被提起的记忆」里有一个表单，**鼠标键盘直接改**，改完点保存就写进 profile 的 `cordis.patch.yml`。

想直接编辑文件也行：`~/.dsh/profiles/<名字>/cordis.patch.yml`。

### 换成你自己的记忆文件夹

如果你已经有一套笔记，直接把文件夹指过去：

```yaml
- id: ofttold-memory
  name: dsh-ofttold-memory
  config:
    memoryDir: ~/notes
    sections:
      - 常被提起（上限 8 条）
      - 我是谁
```

`memoryDir` 是文件夹，`sections` 是要取的小节名——**直接写标题就行**，不需要写文件路径。默认都在 `memoryDir` 下的 `MEMORY.md` 里找。

### 一节要特殊对待时

极少数情况下，某一节在别的文件里、或者要单独给个预算/显示名，用对象写法：

```yaml
    sections:
      - 常被提起
      - file: OTHER.md      # 同文件夹下的另一个文件
        heading: 硬约定
        maxChars: 300
        label: 约定          # 注入块里显示的名字
```

**只有这一种情况需要对象写法**，平常写字符串就够了。

### 标题要一字不差

`heading` 是**精确匹配**：去掉 `#` 之后的原文，一个字都不能少。文件里写的是 `## 常被提起（上限 8 条）`，那整串就是标题——写短的 `常被提起` 找不到，注入块里会报 `heading_not_found`，而不是猜一个最像的。

这条是有意的：**猜错了比报错更坏**。改标题就该让它停下，而不是悄悄换成邻居那一节。

## 给有心人：这套机制背后的想法

这一节解释「为什么这样设计」。不感兴趣可以跳过——上面那些已经够用。

### 为什么要有上限

锚点区上限 8 条，不是随手定的：8 条 ≈ 283 token/轮。这是**成本与余量的交点**——再少，常驻的价值抵不上配置的麻烦；再多，每轮都在为一个很少用得上的清单付钱。

有了上限，就必须有「挤谁」的规则。**而「挤掉」这个动作本身就是一次排序**——比「想起就随手加一条」可靠得多，因为后者从来不删，最后变成一份谁都不看的清单。

### 遗忘曲线（`R = exp(-t/S)`）

挤人的时候按权重算，不按「谁更老」：

```
R = exp(-t/S)     t = 距今天数
                  n = 被几天提起过
                  S = 1 × 2^n
```

**每被提起一次，`S` 翻倍**——这就是间隔重复（SM-2 的首间隔 1 天、FSRS 的可提取性形式），不是拍的。举例：6 天前、被 3 天提起 → `S=8`、`R=0.47`；1 天前、被 2 天提起 → `S=4`、`R=0.78`。

**为什么不用「年龄」单独决定**：实测最老的那条恰恰被引用最多。纯按年龄衰减会把它排到末位——那是错的。

**权重不负责排序，只负责「挤谁」**。平时根本用不上：装得下的时候排序没有意义。只有「满了、新的要进来」那一刻才用它决定谁出去。所以算错了的代价是某条锚点少挂几天，不是数据损坏。

计数是机器活，判断是人的活：`grep -o "2026-10-[0-9][0-9]" diary/*.md` 按来源天去重，就得到「这天被几天想起过」——**同一天提 10 次也只算 1 分**，因为「那天被想起过」是一次事实，不是十次。

> 这个插件**不替你算权重**。它是那个「挤谁」的判断发生时你手边的一份清单。真要算，上面这套就是算法。

### 情绪标签

日记里每一节带一个情绪名（`情绪：<词>`），从一张**封闭词表**里挑——可加，不可删、不可改名。

为什么封闭：`relationship.md` 里有个「情绪缓存区」，只放「我现在」的情绪。缓存区里的词必须是日记标签的**子集**，否则「撞得上」这件事无从发生。

- **日记标签是固化值**：写那段当时的情绪，写完就不变。
- **缓存区是活值**：此刻的情绪，随对话变。

实测为什么必须封闭：现成 5 条情绪记忆里，**5 条 5 种情绪、每种只出现 1 次**——那不是缓存，是一张清单。缓存要有内容，得同一情绪撞到 ≥2 次。**而撞上的前提就是名字统一。**

**不是事后从文字里 grep 情绪词。** 实测 4/5 条情绪记忆根本没有情绪词可撞，因为写下来时情绪已经被翻译成判断了（写的是「我把不忍心当成了不负责」，「不忍心」三个字里已经没有原始情绪）。前者是当下，后者是回顾；回顾拿到的永远是残渣。

> 这个插件**不打情绪标签**。标签是你写日记时自己填的；插件只负责把它带进上下文。

### 为什么不做自动写入

读取是只读的，每个字段都是人工配置——**模型没办法给自己加上下文**。

这是刻意的：一个能自己写记忆的 agent，会把「刚才想到的」和「反复被提起的」混在一起，几轮之后那份清单就不再可信。**记忆的价值来自它是别人挑过的**。

---

## 这个插件刻意不做的事

不打分、不做衰减曲线、不打情绪标签、不猜「重要性」。这些需要判断，而判断恰恰是注意力满的时候最先失效的东西。这个插件只把一份**人写的**清单摆到眼前。

什么重要，仍然是你决定的；它只负责让那份清单不再隐形。

---

## 为什么需要 `refreshAfterMessages`

上下文压缩器会把旧消息折成摘要。注入块就是一条旧消息，所以压缩激进一点的会话最终会把它折掉。一个「注入一次就相信它一直在」的插件，在没被折掉之前都很好用。

`refreshAfterMessages` 在消息数超过阈值时重新注入。这是个近似——压缩会重写载荷但不增加消息数，所以消息数并不直接衡量压缩——但压缩和消息增长是相关的，而判断错的代价是多注入一次。

## 跨平台

**Windows / macOS / Linux 都能跑。**

处理了这几件实际会遇到的事：

| 情况 | 处理 |
| --- | --- |
| UTF-8 BOM（记事本、部分 VS Code） | 剥掉。否则它粘在第一个标题上，精确匹配失败、整节静默消失 |
| CRLF 换行 | 归一化成 `\n`。否则 `\r` 会留在注入文本里 |
| `~\notes` 反斜杠路径 | 和 `~/notes` 一样展开。否则会被解析成进程目录旁边一个字面叫 `~` 的文件夹 |
| 盘符路径 `C:\...` | `isAbsolute` 认得，直接用 |
| 只读的 home 目录 | 不抛错，只记一条 warn——读不了家目录不该让会话起不来 |

`package.json` 里 `engines.node` 是 `>=22.0.0`，三平台一致。

**没做的**：Windows 上的真实设备测试。代码路径都按上面处理了，但「跑得通」是照 Node 的跨平台语义推的，不是我在这台 Mac 上验过 Windows。**这是实话，不是免责声明。**

---

## 出错时

文件没了、标题改了、文件夹读不了，都**不抛错**，而是在注入块里写一行 `Unavailable: <名字>: <原因>`。悄悄跳过一条提醒，比整个 harness 起不来便宜太多。

如果**一节都没读到**，就整个跳过不注入——不花 token 去说一句「什么都没有」。

## 开发

```sh
npm test
```

四个测试文件，按真实度递增：

- `test/sections.test.mjs` — 标题解析（含 `#` 的围栏代码块、四个反引号的围栏不能被里面三个反引号的行关掉）、精确匹配提取、行边界截断、`~` 展开、文件缺失、BOM/CRLF、成功与失败的混合渲染。
- `test/plugin.test.mjs` — 对假 harness 验证决策逻辑：只注入一次、按配置重注入、不在轮中注入、什么都没读到就沉默；另外验证首次运行会建起始文件、以及**相对文件夹不会被建到进程目录**。
- `test/contract.test.mjs` — 同一套 projection 用真 `Session` 和真 `createUserMessage` 驱动，`user/message` 或 `MessageSource` 契约变了会在这里红。
- `test/registry.test.mjs` — 插件挂在真 Cordis `Context` 和真 `SessionProjectionRegistry` 上，证明 key、state schema、reducer 真的注册成功并被驱动。

**判断一个测试有没有价值，就问一句：它手里那个 ctx 是真的吗。** 假 harness 测得了决策逻辑，测不了契约。
